# 技术交底书

## 一、发明名称

一种基于编译型规则 DSL 与多级时间确认的工业边缘告警方法及系统

## 二、技术领域

本发明涉及工业物联网、边缘计算与设备监控领域，尤其涉及一种在边缘侧对设备数据进行采集、规则判断、告警去抖与本地持久化的方法。

## 三、背景技术

工业现场的 PLC、传感器和仪表通常通过 Modbus TCP 等协议输出周期性数据。边缘网关需要在本地完成数据采集和异常判断，并将结果提供给现场看板或上层系统。

现有方案通常存在以下问题：

1. 告警阈值和逻辑硬编码在 C++ 代码中。修改规则需要重新编译、发版和重启，现场调试成本高，非开发人员无法独立维护。
2. 直接在采集线程中执行规则判断、磁盘写入和网络推送。任一环节变慢都会反压采集，导致轮询周期漂移、数据延迟累积。
3. 仅使用瞬时阈值判断。工业信号存在噪声和短时波动，容易产生大量“抖动告警”；若简单增加固定延时，又难以支持恢复侧的独立阈值和持续时间。
4. 断电或异常退出后，内存中的时序数据直接丢失；简单追加日志又缺少记录边界校验与损坏尾部的恢复能力。
5. 告警计算层缺少静态校验，部署后才发现指标名拼写错误、类型不匹配等配置错误。

## 四、要解决的技术问题

本发明要解决的技术问题包括：

- 如何让现场人员以可读规则配置告警逻辑，同时避免每次采集都解释规则文本带来的开销；
- 如何在不阻塞采集链路的前提下完成规则判断和持久化；
- 如何减少工业信号抖动导致的误告警，并支持可配置的恢复滞回；
- 如何在电源异常/进程崩溃后恢复最近时序数据并自动处理不完整日志尾部。

## 五、技术方案

本发明提供一种工业边缘告警方法，包括以下步骤：

### 1. 规则 DSL 的编译与执行

定义面向设备指标的规则 DSL，规则至少包含触发条件、可选的持续时间、可选的恢复条件、恢复持续时间以及告警元数据。网关启动时：

1. 词法分析器将规则源文本转换为带行号、列号的 Token 序列；
2. 递归下降语法分析器按优先级生成抽象语法树（AST）；
3. 依据设备指标注册表进行静态类型检查，确认指标存在，并将指标引用解析为全局指标标识；拒绝布尔与数值混用、非布尔根条件等错误；
4. 字节码编译器将 AST 编译为栈式字节码；逻辑与/或采用条件跳转实现短路求值，跳转位置在单遍生成过程中回填；
5. 采集样本到达时，由栈式虚拟机执行字节码，获得布尔结果，避免运行时重复解析规则文本。

### 2. 多级时间确认的告警状态机

对每条规则实例维护第一状态与第二状态：

- 第一状态（待触发）：触发条件连续为真达到第一持续时间后，生成触发事件并进入第二状态；条件提前为假则清空计时。
- 第二状态（已激活）：若存在恢复条件，则恢复条件连续为真达到第二持续时间后生成恢复事件并返回第一状态；恢复阈值可不同于触发阈值，从而形成滞回。若未配置恢复条件，触发条件变假时立即恢复。
- 计时使用样本采集时间戳而非系统墙钟，使离线回放和自动化测试具有确定性。
- 仅当规则引用到的全部指标均已有有效样本后才评估该规则，避免启动阶段因数据不齐产生误报。

### 3. 采集与处理解耦

每台设备由独立采集线程按轮询周期读取，并将样本写入该设备专属的、容量固定的单生产者单消费者（SPSC）环形队列；单一处理线程以批量、轮转方式消费各设备队列，依次完成时序存储、异步 WAL 入队与规则评估。队列满时不阻塞采集线程，而是丢弃样本并累计可观测的丢弃计数，实现可控背压。

### 4. 时序存储与可恢复日志

每个指标使用定长环形缓冲区保存最近样本，并按时间范围和容量淘汰；查询超过点数上限时，按桶提取最小值和最大值，以保留瞬时尖峰。

持久化采用带 schema 记录与 CRC32 的二进制 WAL：

- schema 记录保存指标标识到稳定指标键的映射；
- sample 记录保存指标标识、采集时间戳与数值位模式；
- 记录由类型、长度、载荷与校验值组成；
- 写入线程通过有界队列异步批量写盘并按周期同步；
- 启动恢复时顺序校验记录，遇到长度越界、校验失败或不足一条完整记录的尾部时，保留此前完整记录并截断损坏尾部。

### 5. 实时输出

通过 HTTP 接口提供设备快照、告警历史、时序查询与规则列表；通过 Server-Sent Events（SSE）向监控页面推送实时样本和告警。每个 SSE 客户端拥有独立有界事件队列，慢客户端丢弃最旧事件而不阻塞处理线程。

## 六、有益效果

与现有常见方案相比，本方案具有以下有益效果：

1. 规则编写与 C++ 发布解耦；未知指标、类型错误在启动期即可发现，并可通过反汇编检查编译结果。
2. 字节码执行减少热路径的解释开销，短路跳转避免无必要的右侧求值。
3. 触发/恢复双阈值与双持续时间的状态机显著降低工业信号抖动造成的误告警，同时保持可配置性。
4. 每设备有界 SPSC 队列与单消费者批处理在不阻塞采集的前提下隔离慢业务，丢弃计数可用于运维告警。
5. schema + CRC + 尾部截断的组合在保持日志格式简单的同时，提供可诊断的断电恢复能力。
6. WAL 异步写入和 SSE 有界扇出避免持久化或慢客户端拖垮采集与规则线程。

## 八、具体实施方式

在一具体实施例中，边缘网关运行于 Linux 或 Windows，通过 Modbus TCP 从站读取保持寄存器与线圈；设备配置包括主机、端口、从站地址、轮询周期与指标映射。网关内置开发用 Modbus 仿真器，生成温度、压力、流量等连续数据。

规则示例：

```text
rule boiler_overheat "1号锅炉温度过高" {
    when boiler_01.temp > 85.0
    for 3s
    clear when boiler_01.temp < 80.0 for 3s
    emit {
        severity = critical
        code = BOILER_OVERHEAT
        message = "1号锅炉温度超过 85℃，请检查燃烧与循环系统"
    }
}
```

该规则被编译为加载指标、常量比较和条件跳转等字节码。温度采样值连续 3 秒高于 85.0 时生成触发事件；之后仅当温度低于 80.0 并连续保持 3 秒时生成恢复事件。

在另一实施例中，采集线程可以将多指标按功能码和连续地址合并为一次 Modbus 读取；对 `f32` 指标按两个 16 位寄存器还原 IEEE-754 位模式，再应用缩放和偏移。

在另一实施例中，WAL 损坏时可将原文件重命名保留并新建日志，而不是直接覆盖；或者为 WAL 增加分段滚动与压缩，以控制磁盘占用。SSE 也可替换为 WebSocket；HTTP 服务可替换为异步 reactor 以支持更多连接。

以上实施例仅用于说明技术方案，不用于限制保护范围。
